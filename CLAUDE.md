## Build/run commands

```bash
cd prototype
npm install          # install dependencies
npm run dev          # dev server at http://localhost:5173
npm run build        # type-check (tsc -b) + production bundle (vite build)
npm run lint         # ESLint across prototype/
npm run preview      # preview production build
```

No test framework is configured.

## Project structure

The repo is a **Savvas Data Show** prototype — an embedded data-exploration feature for high school math textbooks (enVision Algebra 1, Geometry, Algebra 2). The code lives under `prototype/`.

```
prototype/
  src/
    data/             # 40+ dataset modules — each is a .ts file exporting a Dataset object
                      # with attributes, rows, provenance, story, chapterFits, and optional
                      # geo/timeline/featured config. registry.ts collects them all.
    lib/              # Core types (Dataset, Attribute, Row, Provenance), stats helpers,
                      # fit functions, audio WebAudio helpers, useDocumentTitle
    components/       # Shared UI: InputWidget (feedback), Masthead, LessonShell,
                      # ActHeader, ProgressDots, Slider, Spectrogram, Tour, SavvasVideoEmbed
      explorer/       # Dataset-agnostic CODAP-class explorer: ScatterView, BarView,
                      # BoxPlotView, HistogramView, MapView, SkyView, DataTable,
                      # FilterPanel, StatsPanel, ChartToolbar, ColorScale
    screens/          # Page-level route components
      lessons/        # 9 data-literacy lessons (TidyData, SliderOfLies, etc.)
      datasets/       # Dataset library hub + story page + dictionary page
      wind/           # Wind Power Curve activity (3-Act + Quest-format prototype)
        prototype/    # Scene-based "Quest" rebuild with cinematic backdrops
        chips/        # Notice/wonder/claim chip catalogues
        lenses/       # Fit/Differences/Regime lens components
        reveals/      # Reveal cards answering each wonder
      quakes/         # Map Earth's Anger activity (3-Act, same pattern as wind)
      census/, constellation/, hurricane/, inverse-square/, kepler/, moore/,
      reaction/, voice/  # Other activity routes
  public/             # Static assets: audio, images, narrator portraits, SVGs
  scripts/            # Node scripts to generate narrator audio (TTS) and portraits
  api/                # Vercel serverless functions (input-feedback endpoint)
```

## Architecture & key patterns

### Two deployments share one codebase
`VITE_PITCH_MODE=true` switches the app to a stand-alone alignment page. Otherwise the full prototype renders with all routes.

### The 3-Act spine (non-negotiable)
Every chapter activity follows Savvas's **Identify · Model · Interpret** framework:

- **Act 1** — Notice & Wonder: students watch a data reveal, then pick notice/wonder chips
- **Act 2** — Investigate: students work lenses (fit, differences, regimes) and pick claim chips
- **Act 3** — Reveal: data answers the wonderings, students commit to a final claim

This structure is enforced by `<ActFrame>` / `<SceneFrame>` + `<ActRail>`. New activities must slot into this spine (see [memory: acts-are-the-base]).

### Scene-based "Quest" format (wind prototype)
The newer `WindScenePrototype` replaces the single-page activity with 10 scenes across 3 Acts. Each scene uses `<SceneFrame>` which handles: cinematic between-scene pause with themed backdrop, act rail, title cards, and Back/Next navigation. Backdrop variants are defined in `backdrops.tsx`. The goal is to move toward this format.

### Dataset system
40+ datasets follow a common `Dataset` interface (defined in `lib/dataset.ts`). Each dataset module exports a `Dataset` object with `attributes`, `rows`, `provenance` (required — with primary source URL, retrieval method, license), `story`, `chapterFits`, and optional `geo`, `timeline`, `featured` (default chart config). The CODAP-class Explorer (`src/components/explorer/`) renders any dataset — scatter, bar, histogram, box plot, map views.

### Design system
Tailwind CSS with custom brand palette: navy `brand-*`, amber `accent-*`, warm `surface-*`, and `ink-*` tones. Typography: Fraunces (display serif), Inter (sans), JetBrains Mono (mono). See `tailwind.config.js`.

### Narrator system
Activity-specific narrator personas (e.g., Dr. Marcus Vela for wind) with scripted dialogue lines stored in JSON, voiceover MP3s generated by `scripts/generate*.mjs`, and React components (`NarratorSays`, `NarratorBubble`) for in-activity display with play/pause audio.

### Feedback InputWidget
Every route has an `<InputWidget>` that lets reviewers edit any text/heading or leave comments. Posts to a Vercel serverless function at `/api/input`.
